# Lab 7 – Wireframes Findings

## Part A – Requirements Review
- Students should be able to view available equipment.
- Students should be able to submit equipment requests.
- Staff review requests before making a decision.
- Open question: How is equipment availability confirmed?

## Part B – Equipment Request Prototype
The prototype contains five screens:
1. Browse Equipment
2. Equipment Details
3. Request Equipment
4. Missing Date Feedback
5. Request Submitted

## Part D – Walkthrough Findings

1. The Browse Equipment screen clearly presents the available equipment choices.
2. The Request Equipment screen shows start date and end date fields.
3. The Missing Date screen displays an error when the end date is missing.
4. The final screen clearly explains that the request is awaiting staff review.

### Suggested Improvement
Make the missing end-date message easy to notice and ensure users understand that submitting a request does not mean it has been approved.

### Open Questions
- Does the system require both dates before submission?
- How will students know when staff make a decision?
- How is equipment availability checked?

## Review Method
Self-review of the low-fidelity prototype. No real stakeholder approval was obtained.
